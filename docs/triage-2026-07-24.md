## 이슈 1. 미션 카드 연타 시 크레딧/하트 손실 — 원인 확정 ✅

**증상**: 카드 3장 연타 → 크레딧 +60 기대인데 +20만 반영, 하트 증가 없음. 화면에선 올라갔다 롤백.

**원인 (코드 검증됨)** — 두 겹의 문제:

1. **서버: Lost Update 경쟁 (실제 데이터 손실, 핵심)**
   `src/app/api/daily-mission/complete/route.ts`
   - 116행: `child_stats`를 **먼저 읽고**(statsPeek)
   - 248~269행: 읽은 값 기준 **절대값으로 UPDATE** (`credits: baseCredits + creditEarned`)
   - 동시 요청 N건이 **같은 base를 읽고** 각자 base+10을 써서 마지막 쓰기만 살아남음.
   - 카드가 사라지는 건 정상( daily_missions 행별 업데이트는 충돌 없음 ) → "카드는 사라졌는데 보상만 손실"과 정확히 일치.

2. **클라이언트: 동시 요청 허용**
   `src/components/child/ChildScreen.tsx` 1652~1688행
   - 3초 내 연타는 4번째까지 그대로 `commitMissionComplete` → 각 탭이 **독립 fetch를 즉시 발사** (직렬화 큐 없음). 5번째부터만 확인 팝업.

3. **화면 롤백 연출 (표시 문제, 부차)**
   - 느린 `/home` 재조회(RSC)와 `trg_mission_logs_recalc_eq` 트리거가 만드는 Realtime 중간값이 로컬 낙관값을 덮어씀.
   - 가드 수정은 `claude/ui-background-tweaks` 브랜치에만 적용됨 (main 미적용).

**수정 방향(제안)**: ① 서버를 원자적 증가로 전환 — `SET credits = credits + X` RPC (레벨/EXP는 RPC 내부 계산 또는 재계산), ② 클라이언트 완료 요청 직렬화 큐. 권장: ①+② 병행. ③ 화면 가드(브랜치 커밋 141a89b·8a3dcbd)를 main에 반영.

## 이슈 2. 화분 — 씨앗심기 팝업 돌발 + 물주기 잠김 — 원인 확정 ✅

**증상**: 단계 업그레이드 때 갑자기 씨앗심기 팝업 → 이후 하트가 있어도 물주기 불가, 단계 안 오름 → 새로고침하면 정상.

**원인 (코드 검증됨)** — `src/hooks/usePlantPot.ts`:

1. **물주기 잠김 (영구 잠금 누수)**
   - 낙관적 레벨업 순간 `stageTransitionLockRef = true` (514~522행). 해제는 **오직 축하 팝업 닫기**(`dismissPlantCelebrate` → `unlockStageTransition`, ChildScreen 768~772행)뿐.
   - 완성(7단계) 경계에서는 즉시 팝업을 안 열고 **서버 응답을 기다림**. 그런데 서버 실패/불완전 응답/네트워크 예외 시 `'ok'` 반환 (581~597, 620~624행) → **축하 팝업이 안 열림 → 잠금 해제 경로 자체가 사라짐** → 이후 모든 `water()`가 `'locked'`.
   - 새로고침 시 ref 초기화로 회복 — "새로고침하니까 다시 됨"과 정확히 일치.

2. **씨앗 팝업 돌발**
   - 낙관적 계산만으로 `newStage===7 → completed=true` 설정 (490~510행). `needsPotSeedSelection`은 `stage===7 && completed`면 즉시 true (`src/constants/plantTrees.ts` 212행) → `PlantPot`이 씨앗 카드 표시 (286행). **서버 확정 전** 클라이언트 오판만으로 뜸.
   - 완성 오판 시 `potGeneration` 증가(531행)로 큐의 후속 물주기 요청이 통째로 폐기됨 → "단계가 안 오름" 가중.
   - 이슈 1의 하트 lost update가 화분 하트 값을 흔들어 경계 오판(스테일 heartsUsed/heartsNeeded)을 유발할 수 있음 — 두 이슈는 연관.

**수정 방향(제안)**: ① 잠금에 타임아웃/실패 시 자동 해제(실패 경로에서 `unlockStageTransition` 호출), ② 완성 판정은 서버 확정 후에만 `completed` 반영, ③ 이슈 1 해결로 하트 정합성 확보.

## 이슈 3. 자정에 당일 미션 카드가 바로 안 뜸 — 부분 검증 + 배포 확인 필요 ⚠️

**코드상 리셋 체계는 3중으로 존재하며, repo 코드는 모두 서울 날짜 기준으로 정상**:

| 경로 | 위치 | 상태 |
|---|---|---|
| 클라이언트 자정 타이머 + 포커스 복귀 시 날짜 점검 → `router.refresh()` | ChildScreen 978~1025행 | ✅ 정상 |
| `/home` 로드 시 부족분 백필 (서울 날짜, upsert) | home/page.tsx 85·285~313행 | ✅ 정상 |
| 자정 크론 Edge Function | `supabase/functions/generate-daily-missions` (83행 서울 날짜) | ⚠️ 배포 상태 불명 |

**확인 필요한 것 (repo 밖)**:
- `supabase/config.toml`이 repo에 **없음** → 크론 스케줄이 코드로 관리되지 않음. 대시보드 설정 여부·주기 확인 필요.
- Edge Function은 git push로 배포되지 않음(supabase CLI 수동 배포). **배포본이 구버전(UTC 날짜 스탬프)일 가능성** — 7/23 DB에서 UTC 날짜로 찍힌 생성 배치가 관측된 것과 부합. UTC 날짜면 서울 자정에 "어제 날짜"로 생성 → 당일 카드 없음.
- 확인: Supabase 대시보드 → Edge Functions → 최근 배포일/로그, 크론 잡 설정.

**체감 "바로 안 뜸"의 보조 요인**: 크론이 못 만들면 카드 생성이 `/home` 접속 시 백필로 미뤄지는데, 백필은 upsert+전체 재조회 왕복이 추가되어 첫 화면이 늦음(+ dev 컴파일 지연).

## UI 개선 요구사항 정리 (논의/구현 대기)

### A. 부모 홈 화면
- **AI 리포트 그레이 박스(준비 중) 전체 삭제** — 분석 데이터·저축 습관·레벨 분석·경제 지수 그래프 포함.
- **한 블록 3단 구성**: ① 오늘의 진행도(원형 도넛, 중앙에 % 표시) ② 주간 루틴 완료율(영역 축소) ③ 루틴 완주율.
- 그 아래 **다가오는 일정** 블록 → 그 아래 **캘린더**.

### B. 루틴 탭
- 캘린더가 홈으로 이동했으므로 공간 활용: **접힘 블록 기본값을 모두 펼침**(원하면 토글로 닫기).
- **태블릿: 좌 일상 미션 / 우 스페셜 미션** 2열 배치.
- 키워드 추가/삭제 방식은 유지(온보딩 연동).
- **드래그앤드롭 순서 변경 안내 메시지** 노출.
- 연필 아이콘 → **"미션 수정하기" 텍스트 버튼**으로 (스페셜 동일).
- "상품 추가하기·미션 수정하기·최근 구매내역·일정 추가하기" 등 액션을 **눈에 띄는 블록 버튼**으로.

### C. 커스텀 미션 (사용자 요청 기능)
- "미션 수정하기" 팝업 하단에 **커스텀 루틴 추가하기** 버튼.
- 입력: 오전/오후 구분, 이미지, 제목, 보상 정보.
- 추가 시: 키워드 목록에 등록 + **루틴에 바로 추가(디폴트 on)** + 루틴 탭에서 추가된 카드 위치로 스크롤해 바로 보여줌.
- 스페셜 미션도 동일: 카테고리(집안일/예절/건강·미용 등) 직접 선택 후 추가.

### D. 승인 탭
- 모바일: 칭찬스티커 보상 → 오늘 완료 미션 → 구매요청 → 메뉴제어 순.
- 태블릿: 좌(칭찬스티커, 오늘 완료 미션) / 우(구매요청, 메뉴제어).

### E. 플로팅 아이콘
- 기기별 위치 편차(갤럭시 폴더블에서 중앙 근처) → **항상 화면 우하단 고정**으로 수정.
