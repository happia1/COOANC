# 개선 작업 반영 현황 — 2026-10-26

## 코드에 반영한 내용

- 미션 완료·로그·보상은 `apply_daily_mission_action`의 한 트랜잭션으로 처리한다. 보상값은 DB의 미션 설정에서 계산하며 기존 배수·XP·스트릭·배 이동·EQ 순서를 유지한다. 잔액으로 지급 여부를 추측하는 절대값 폴백은 삭제했다.
- 자녀 스탯 잠금 → 일일 미션 잠금 순서를 완료/취소에서 공유한다. 완료 버전과 요청 ID로 중복 지급을 막고, 취소 뒤 새 완료는 허용하며 이전 완료의 늦은 재시도는 거절한다. 부모 취소도 화면에서 본 완료 시각을 검증한다.
- 미션·저금통 이체/보너스·구매·물주기·씨앗 구매가 자녀별 작업 순서를 공유한다. 저금통은 350ms 연속 입력 묶음을 유지하면서 첫 탭에 순서를 예약한다. 다른 거래를 사이에 두고 새 입력을 앞의 묶음에 합치지 않는다.
- 결과가 불명확한 실패는 이후 계산을 막고 저장 결과 재확인을 안내한다. 완료·물주기 재전송은 같은 요청 ID로 수행한다. 구매는 확인창을 닫는 늦은 시점에 옛 잔액을 다시 적용하지 않는다.
- 물주기는 하트 차감·성장·수확을 DB 안에서 함께 저장한다. 하트 비행 효과는 응답 전에 시작하고 일반 탭에서 홈 전체 스탯의 낙관적 변경을 함께 수행하지 않는다. 성장 그림과 축하는 확정 결과에 맞추며 하트 비행 도중 축하창이 덮지 않게 한다.
- 성장 결과는 확인 여부를 기록해, 응답 유실/재접속 후에도 확인하지 않은 축하를 복구한다. 확인 저장이 성공한 뒤 다음 물주기를 허용한다.
- 마켓·스티커 보관함·꾸미기·콘텐츠 상세는 아이콘을 열 때 인증 후 조회한다. 실패는 빈 목록으로 처리하지 않는다. 홈에는 실제 필요한 미확인 스티커 알림과 저장 상태만 남긴다.
- 화분 초기 상태는 홈의 저장 스탯·씨앗 선택 이력으로 표시한다. 정상 진입에서 같은 화분 상태를 다시 읽지 않는다.
- 로그인 성공 응답에서 목적지·부모의 자녀 미리보기 쿠키를 함께 준비한다. 역할은 편집 가능한 사용자 메타데이터 대신 프로필로 확인한다. 기존 P2 인증 요청 순서 보호를 유지한다.
- 한국 시간 자정 예약은 `prepare_child_mission_cards`로 미션 카드만 생성한다. 자녀 연결·활성·레벨·평일/주말·개별 날짜 설정·스페셜 조건을 적용하며 기존 카드를 덮어쓰지 않는다. 다른 아이콘과 잔액/화분은 예약 대상이 아니다. 접속 시 누락 보충 경로도 유지한다.
- `/assets/` 공개 정적 파일은 인증 미들웨어를 거치지 않게 했다. 효과음을 처음 재생할 때 불필요한 Auth 요청이 발생하는 경로를 제거한다.

## 추가로 발견한 공개 키 문제

로컬 공개용 환경 변수와 현재 공개 배포의 로그인 JavaScript에서 관리자 역할 키가 사용되는 것을 확인했다. 키 값은 이 문서에 기록하지 않는다. 이 문제는 일반 RLS/함수 권한 수정만으로 해결할 수 없다.

- 로컬 `.env.local`의 공개용 키를 프로젝트의 publishable 키로 교체했다.
- 관리자 키가 `NEXT_PUBLIC_SUPABASE_ANON_KEY`에 들어가면 빌드 및 클라이언트 생성이 실패하도록 검사한다.
- 새 로컬 빌드의 공개 파일 53개 검사에서 관리자 역할 키는 발견되지 않았다.
- 2026-10-27 사용자 MFA와 값 저장 후 공개용/서버용 키를 반영한 운영 재배포가 완료됐다. 배포 `42oQKC143r81bN8tGUV1NTtLMM3D`, 소스 `86ba695`, 운영 도메인 `cooanc.vercel.app`의 Ready 상태를 확인했다.
- 운영 로그인 응답 HTTP 200 및 공개 JavaScript 12개에서 올바른 publishable 키를 확인했다. 관리자 역할 JWT와 서버 secret 키는 발견되지 않았다. 로컬 서버 설정도 유효한 현대식 secret 키로 맞췄다.
- 노출된 이전 JWT 기반 API 키의 비활성화는 사용자의 직접 완료를 기다리는 중이다. 새 배포의 키 교체만으로 이전 배포에 남은 키가 무효화되는 것은 아니다.
- 공개용 키와 서버 전용 secret 키를 각각 Vercel에 설정하고 재배포한 뒤, Supabase의 이전 JWT 기반 API 키를 비활성화해야 한다. 이전 배포/미리보기 번들에 남은 키도 더 이상 작동하지 않게 해야 한다. 기존 서버가 옛 키를 쓰는 동안 먼저 비활성화하면 운영 기능이 중단된다.

공식 절차: https://supabase.com/docs/guides/getting-started/migrating-to-new-api-keys

- 미션 예약 함수: 주말 custom 루틴·스페셜·레벨 필터, 반복 실행 무변경, 금액/하트/화분 무변경, 익명 내부 RPC 거절.

- 임시 계정과 테스트 데이터는 각 검사 종료 시 삭제했다. 실제 사용자 잔액은 변경하지 않았다.
